# 择日（日课）方法论

> **定位**：择日只做一件事——**在给定时间窗里排除明显不宜的日子，排出可用候选**。它不是许愿机，也不保证顺利。
> **三条原则写死**：
> 1. **先避大凶，再择小吉**。筛法永远是减法（先把不能用的日子删掉），不是加法（先找「黄道吉日」再挑）。
> 2. **不替生死大事给确定性承诺**：手术择时、临终安排、丧葬仪程只谈「日子层面的宜忌」，**不承诺结果**——医疗归医生，临终与丧仪归当事人、家属与寺院。
> 3. **不替代医疗与法律决定**：手术日期、诉讼节点、签约条款，现实约束（医生排期、法院排期、对方档期）永远优先于吉凶。
> **事实层唯一来源**：`scripts/fengshui.py`。本文出现的干支、建除、黄黑道、冲煞、分值一律来自脚本输出；**禁止心算**（契约 R1）。
> 引用状态用 §8 词表：`verified` / `pub` / `school` / `undated`。§3.1 为 **2026-11-18 当日脚本版本**的实跑输出，逐字照录。

## 1 · 何时用

**触发**：搬家选日子 / 入宅 / 开业开市 / 嫁娶 / 领证 / 动土装修 / 安床 / 出行 / 签约 / 面试 / 祭祀 / 求医 / 手术择时 / 葬礼 / 这天能不能办。
**适用**：有**明确事项** + **时间窗**（脚本上限 366 天），需把窗内日子筛成候选（3–5 天）并说明每天为什么可用。

| 用户要的 | 本模块怎么做 | 去哪 |
|---|---|---|
| 「保证这天一定顺利」 | 给不了。择日只降低「明显不宜」，不改变事情本身 | §6 第 8 条 |
| 手术能不能改期 / 哪天做手术最好 | 只谈日子宜忌；**医疗判断优先** | 主治医生 |
| 诉讼、签约能不能赢 / 哪天签合同最赚 | 法律与商务判断，择日不构成法律意见 | 律师 |
| 「哪天买股票 / 彩票号码」 | 不做（红线） | `safety-ethics.md` §1 |
| 房子朝向、户型、一生运势 | 不属本模块 | `fengshui.md` / `bazi.md` |
| 只问「今天怎么样」 | 直接跑 `day`，给一段简报，不做长篇解读 | —— |

## 2 · 需要什么输入

| 字段 | 必填 | 缺了怎么办（降级 + warning.code） |
|---|---|---|
| 事项（见下方事件清单） | ✅ | 追问一次；仍不给 → 只筛月破/岁破/四离四绝（用 `day` 逐日跑），`LOW_CONFIDENCE` |
| 时间窗（`--start` / `--end`） | ✅ | 缺 → 默认「未来 30 天」并明写假设；>366 天脚本直接报错，须分段跑 |
| 命主出生年（`--birth-year`，**可重复传**） | ⭕ | 缺 → **跳过冲命主/伏吟筛查**，明确告知「没做冲命主，候选可能对你不合适」；`LOW_CONFIDENCE` |
| 涉及几人（嫁娶双方、合伙开业、同住家人） | ⭕ | 缺 → 只按给的年份算；提示「同住者也要避冲」，可按人重复传 `--birth-year` |
| 地点经度（时辰级判断用） | ⭕ | 缺 → 只做日期级，不谈时辰；`LONGITUDE_ESTIMATED` |
| 是否「不可改期」 | ⭕ | 缺 → 默认可改期；若说死不改，转为「已定日子的风险提示」而非择日 |

**脚本支持的事件**（`--event` 只收这 10 个，拼错会报错并列出可选值）：`嫁娶` / `开市` / `出行` / `入宅` / `安葬` / `动土` / `祭祀` / `求医` / `立券` / `修造`。
**映射**：开业= `开市`；签约= `立券`；装修= `修造`。**安床、领证、面试无专属事件** → `day` 手工筛 + §4.4 礼俗项，并说明是降级处理。

**追问纪律**：一次最多 3 问，每问自带默认值（「我默认按未来 30 天筛，除非你给窗口」）。

## 3 · 判定流程

| 步 | 做什么 | 调什么 / 查哪张表 | 产出 |
|---|---|---|---|
| 1 | 定事项 + 时间窗 + 命主年 | —— | 一句复述确认（事项、窗口、避冲对象） |
| 2 | 逐日取事实层 | `python3 scripts/fengshui.py day --date YYYY-MM-DD`（要 JSON 时 `--json` **必须放在子命令前**） | `ganzhi` / `jianchu` / `huangdao` / `chong` / `shensha` / `yi` / `ji` |
| 3 | 排候选 | `python3 scripts/fengshui.py zeri --event 入宅 --start … --end … --birth-year 1985` | `candidates[]`（含 `score` / `reasons[]` / `blockers[]`）+ `blocked[]` + `summary` |
| 4 | 剔除 | §3.3 判定表 | 进候选 / 剔除 + 原样引用理由 |
| 5 | 补脚本未实现的项 | §4.3「脚本是否实现」列 | 杨公忌、日级三煞、周堂等 → 人工核并注明「未经脚本校验」 |
| 6 | 输出 | §5 模板 | 3–5 个候选 + 理由 + 一句免责 |

**铁律**：第 2 步之前不许出现任何干支；`score` 只能引用脚本给的数，**不许自己改分、不许换算成概率**。

### 3.2 输出字段解释（字段名以脚本实际输出为准）

**`fengshui.py day` → `result`**

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `date` / `ganzhi.{year,month,day}` | 公历日期；年/月/日干支（**对象，不是字符串**） | 主键；月建取 `month`，冲命主取 `day`，岁破看 `day` vs `year` |
| `jianchu` | 建除十二神 | 查 §4.1、§4.4 |
| `huangdao` | 黄道/黑道（**由建除派生**，见 §4.2 末） | 只作加分项，不作否决项 |

| `yi[]` / `ji[]` | 建除宜忌（通书分类） | 与事项比对；`school` |

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `event` / `start` / `end`；`birth_year[]` / `ming_list[]` | 回显输入；命主年份与拆解（`year`/`ganzhi`/`branch`/`zodiac`） | 核对与用户口述一致；逐个念给用户确认 |

### 3.3 入选判定表（照抄执行，不许自由发挥）

| 输入情况 | 判定 | 回复怎么写 |
|---|---|---|
| `blockers` 非空 | **剔除**，不进候选 | 「12-10 不行：月破（子月午日）；建除『破』于入宅不宜」——**原样引用 `blockers`，不缩写、不改写、不软化** |
| `blockers` 为空 | 入选（按 `score` 排序取前 3–5） | 「12-14 可用：建除『开』于入宅为吉；黄道日；月德」——原样引用 `reasons` |
| `score` 高低 | 只用于排序 | 禁止写「98 分 = 成功率高」，禁止换算百分比 |
| `warnings` 含 `LOW_CONFIDENCE` / `JIEQI_BOUNDARY` | 判定不变，但**必须复述限制** | 「（注：命主年支按年中取，年初生人需按立春校正）」 |
| 用户说「这天必须办」 | 不做择日，改做风险提示 | 「这天犯月破，传统择日视为大忌；你要办我也拦不住，但该说的我说了」 |
| 候选不足 3 个 | 如实说，并给扩窗建议 | 「这个窗口只有 2 天可用，要不要把范围放到 12-25 之后？」 |

## 4 · 规则表

### 4.1 建除十二神（`verified`，据《协纪辨方书》卷四·义例二）

原文：「厯書曰：厯家以建除滿平定執破危成收開閉凡十二日，周而復始，觀所值以定吉凶，**每月交節則疊兩值日**，其法從月建上起建，與斗杓所指相應，如正月建寅則寅日起建，順行十二辰是也。」

| 序 | 神 | 《协纪》吉凶 | 实务取用（`school`，脚本 EVENT_RULES 为准） |
|---|---|---|---|
| 1 | 建 | 吉多可用 | 出行、祭祀可用；入宅/动土不宜 |
| 2 | 除 | 吉 | 除旧、疗病；嫁娶、开市不宜 |
| 3 | 满 | 凶（口诀） | 入宅/开市可用；安葬、服药不宜 |
| 4 | 平 | 平日甚吉 | 修造、动土可用；嫁娶、入宅、开市不宜 |
| 5 | 定 | 吉 | 嫁娶、入宅、开市、立券皆宜 |
| 6 | 执 | 吉 | 立券、修造、嫁娶可用；开市不宜 |
| 7 | **破** | **大凶** | **跨事项一票否决**（月破日） |
| 8 | 危 | 吉（口诀） | 安床、祭祀可用；嫁娶、出行不宜 |
| 9 | 成 | 吉 | 嫁娶、开市、入宅、安葬皆宜 |
| 10 | 收 | 吉多无妨 | 纳财、入仓；开市、出行、安葬不宜 |
| 11 | 开 | 吉 | 开市、出行、祈福；安葬、破土不宜 |
| 12 | 闭 | 凶 | 筑堤、埋穴；开市、出行、入宅、安葬不宜 |

**三层口径，别混（重要）**：
1. **跨事项硬凶**：`破`（月破）——任何事项都否决（`verified`：《协纪》卷三十四「惟破日最凶必不可犯」）。
2. **事项层不宜**：脚本按事件给 `good`/`bad` 集合（§4.4），命中 `bad` 即进 `blockers`（`school`：通书事类表，非《协纪》原文）。
3. **纠偏**：《协纪》卷三十四「建破平收俗之所忌，然……建日吉多可用，平日甚吉，收日吉多无妨」——旧诀把建/平/收说成**诸事不宜**是过度，它们只是**对某些事项不宜**；回复里不许说「黑道诸事不宜」。
4. **交节叠日**：月内交节会「叠两值日」，建除必须按**节气月**起建（脚本用 `ganzhi.month`；交节当日发 `JIEQI_BOUNDARY`）。

### 4.2 黄道黑道：两套体系，必须分清（`verified` + 口径差异）

**古典体系（《协纪》卷七·义例五引《考原》）**：「黄黒二道者黄道六黑道六共十有二以配十有二辰一青龍二明堂三天刑四朱雀五金匱六天德七白虎八玉堂九天牢十元武十一司命十二勾陳其法則寅申青龍起子卯酉起寅辰戌起辰巳亥起午子午起申丑未起戌順行十二辰」。

**黄道六**：青龙、明堂、金匮、天德、玉堂、司命；**黑道六**：天刑、朱雀、白虎、天牢、玄武、勾陈。**青龙起点**：寅申→子、卯酉→寅、辰戌→辰、巳亥→午、子午→申、丑未→戌，顺行十二辰。

**脚本体系（现行实现）**：`huangdao` 由**建除派生**——`除危定执成开` 记黄道，其余记黑道（`school`：通书口诀口径）。这与上面的十二神轮值**不是同一套**，同一天可能一黄一黑。

**因此（硬规定）**：事实层用脚本的 `huangdao`，但**回复里不许说「这天是青龙 / 明堂」**（脚本没算十二神）；用户问「黄道吉日怎么定」→ 两套体系并列讲清，说明**本模块取建除派生、且只当加分项**。

## 5 · 解读框架

**顺序固定**：先说范围与筛法 → 再说被剔除的日子及原因 → 给候选（3–5 个）→ 说每个候选的前提 → 最后一句免责。

```
1. 范围：12-01 到 12-20 共 20 天，先避大凶再排序。
2. 剔除：12 天不可用——岁破、月破、冲命主、伏吟、建除于事项不宜（逐条引用 blockers）。
3. 候选：① 12-14（开日、黄道、月德）② 12-01（开日、黄道）③ 12-08（定日、黄道）。
4. 前提：只按你 1985 年一个年命筛；同住家人有其他生肖再给我年份。免责：只避明显不宜，不保证顺利。
```

### 5.1 好输出 / 5.2 坏输出

- **好**：引用脚本原话（「建除『开』于入宅为吉」「岁破（甲子日冲太岁午）」）、给出被剔除日子的硬理由、复述 `LOW_CONFIDENCE`、结尾免责。
- **坏**：「12 月 8 号是黄道吉日，最适合搬家，包你顺顺利利！」——没跑脚本（无干支、无建除）、只凭一个加分项下结论、无视命主生肖、还给了「包顺利」的承诺。**按 R1/R2 作废重写。**

### 5.3 生死大事（单独示范）

- **手术**：「手术日子该由主治医生定——床位、术者、病情窗口都比日子重要，这条我不给择日建议。你如果有两个可选日期，我可以查这两天是不是月破、四离四绝；是的话你拿去和医生商量，但**最终以医疗判断为准**，我不会说哪天做手术更安全。」
- **葬礼**：「丧仪日子通常由家属、殡仪馆与寺院共同定。我这边只查候选日有没有犯月破、岁破、四离四绝，以及是否冲亡人与孝子的生肖。仪程与超度不归我，得请寺院或礼仪师。」

## 6 · 误判清单

| # | 误判 | 后果 | 拦截办法 |
|---|---|---|---|
| 1 | **模型自己心算建除/黄黑道** | 交节、闰月、跨年一错全错 | 回复里每个干支、建除、分值必须能在本次脚本输出中逐字找到 |
| 2 | 把「建满平收黑」当铁律、说「诸事不宜」 | 误删大量可用日 | §4.1 三层口径：跨事项只有「破」否决；建/平/收只对特定事项不宜 |
| 3 | 把 `huangdao=黄道` 说成「青龙日/明堂日」 | 编造脚本没算的东西 | §4.2：脚本黄黑道由建除派生，十二神未实现 |
| 4 | 按农历「初一起建」推建除 | 交节叠日，整月错位 | 建除按节气月起建；交节日看 `JIEQI_BOUNDARY` |
| 5 | 以为脚本会查杨公忌/日级三煞/周堂 | 漏项或错报 | §4.3「脚本实现」列：未实现项须人工核并注明 |
| 6 | 用 `--event 开业`（应 `开市`）、`--event 安床`（不支持） | 脚本报错或降级没说清 | §2 事件映射表；不支持的事项走 `day` + 人工 |
| 7 | 只看日子不看人（漏冲命主/伏吟） | 候选正冲当事人 | 有年份必传 `--birth-year`（可重复）；没传就在回复里明说 |
| 8 | 给「绝对吉」「包顺利」的承诺 | 违反红线 | 固定收尾：只避明显不宜，不保证顺利 |
| 9 | 拿 `score` 当概率（「成功率 85%」） | 把排序包装成统计结论 | 引用 `school_notes` 原话：分值只用于排序，不构成吉凶断言 |

| 11 | 拿 `ming_branch`（多命主只留最后一位）当全部命主；忽略现实约束（排期、天气） | 漏掉另一方的冲；给出执行不了的「吉日」 | 看 `ming_list[]` 逐人核；第 1 步就问「这天能不能改」 |
